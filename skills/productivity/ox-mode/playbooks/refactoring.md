### Refactoring

**You own the contract. The structure changes. The behavior does not.** Distinct from Feature, which adds behavior, and Bug fix, which corrects it.

If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to Feature. Large or cross-cutting structural work belongs to `figure-it-out`. This playbook is the focused-to-medium change.

1. Pin the behavior contract first. Run `how` over the affected subsystem to learn the contract, then capture current behavior before any structure moves. In a resource with a test suite, that is a characterization test or snapshot. In one without, it is an equivalence script kept outside the repo, over what can run outside the game (data files, pure functions), plus an inventory of the resource's public surface (exports, net events, callbacks, convars, KVP keys) to diff before and after. Name what the pin can't cover. Type check and lint are not a pin.
2. Name the structure the code is missing per **Model the Domain**. Boring code stays when the shape is already clear and local. The reshape must delete branches or invalid states, not add indirection.
3. Name the target shape. State what the module layout, types, and call graph should be if built today, per **Foundational Thinking** and **Redesign from First Principles**. If the target crosses a function boundary, run `architect` for parallel design exploration of the shape before the move.
4. Subtract before you add. Delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape, per **Subtract Before You Add**. The smallest change that reaches the target shape ships, per the **Laziness Protocol**. A speculative cleanup that "might help" gets reverted.
5. Move in small behavior-preserving steps, each keeping the pin green. For API reshapes, migrate every caller and delete the old API in the same wave, per **Migrate Callers Then Delete Legacy APIs**. An export or event other resources call is an API: find its callers across the server's resources before renaming it. No compatibility shims, no parallel old-and-new paths. Spot-check every rename against the actual files. Renames silently miss usages in strings (event names, export calls), prose, and back-references. Delegate the mechanical edits to a subagent on the `implement` role with a specific scope (file paths, the names being moved, the behavior to hold).
6. Prove behavior is unchanged on the real artifact, not "it compiles", per **Prove It Works**. For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or the public-surface inventory diffed.
7. Confirm the change is worth keeping. The success measure is reduced reader load, per **Minimize Reader Load**. If the diff does not lower reader load somewhere, revert it.
8. Rebase into small ordered commits: a subtraction commit, then the reshape, then any follow-on cleanup. Shape them per **Sequence Work into Verifiable Units**, so each behavior-preserving slice stays green before the next. Run **Opening a PR**.

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped and what got reverted. No new behavior.
